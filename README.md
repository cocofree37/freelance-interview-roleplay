# フリーランス・複業案件 面談準備アシスト

案件のURLを入れて、作りたいものを選ぶだけで、次の3つを作成します。経歴・実績を踏まえた内容になります。

| 出力 | 内容 |
|---|---|
| 応募文 | 案件と経歴から、そのまま送れる応募文。応募フォームの項目名(と文字数の上限)を貼り付けると、項目ごとに書き分け、字数を表示します。段落ごとに1行で、フォームへ直接貼り付けられます |
| 面談資料 | 想定質問と準備事項、経歴との差から「突っ込まれそうな点」、答え方が重要な質問の回答の骨子 |
| ヒアリングテキスト | 案件の不明点を聞く質問リスト(確認する理由つき)と、面談で自分が話すことの整理 |

どの出力を選んでも、あわせて「案件の見立て」(応募推奨・条件次第・見送り推奨、勝ち筋、懸念)と、「確認したいこと」(本文に書けなかった事実への質問)が付きます。確認したいことに答えると、反映して作り直せます。

**アプリはこちら → https://cocofree37.github.io/freelance-interview-roleplay/**

## 文章の考え方

応募の実務をもとに、次の方針で作成します(プロンプトは [worker/src/index.js](worker/src/index.js))。

1. **事実だけを書く** — プロフィール・経歴に書かれた実績と数字だけを使います。確信が持てない事実は、本文に断定せず「確認したいこと」として質問します。
2. **募集要件に正面から応える** — 満たす人が最も少ない要件を先頭に置き、足りない要件は近い実績で橋渡しします。
3. **差別化は本人の数字で語る** — 継続年数・取引社数などで示し、他の応募者には触れず、安さを売りにしません。
4. **条件は先に正直に** — 稼働や単価が希望とずれるときは、先に伝えて相談する形にします。
5. **設問ごとに書き分ける** — 項目間で内容を重複させず、文字数の上限を守り、自己評価は最上位に偏らせません。
6. **応募前に判断する** — 実質時給や条件の食い違いを見て、応募するかどうかの見立てを示します。

## ゲストモードとログイン

| | ゲストモード | ログイン |
|---|---|---|
| 入力内容の保存 | 保存されない | プロフィールと職務経歴書を保存 |
| 経歴の入力 | その場で貼り付け、またはファイルを読み込み(保存されない) | マイページで一度登録すれば、毎回の入力は不要 |
| 1日の利用回数* | 同じ回線から9回、ゲスト全体で60回 | 1人15回、ログインユーザー全体で100回 |

\* 作成するものを1つ選ぶごとに1回消費します(3つ選ぶと3回)。上限の値は [worker/src/index.js](worker/src/index.js) と [supabase/schema.sql](supabase/schema.sql) の定数で変更できます。

ログインはメールに届くリンクを開くだけです。マイページでは、プロフィール(氏名・職種・経歴・希望条件)と、職務経歴書などのファイル(PDF・Word・テキスト、5MB・5件まで)を保管できます。ファイルの原本は本人だけが見られる領域に保存し、AIにはブラウザで取り出した文字だけを渡します。

## 構成

- [index.html](index.html) — トップ画面(案件URLの入力、作成、結果の表示)
- [mypage.html](mypage.html) — マイページ(プロフィール・ファイルの保管と削除)
- [extract.js](extract.js) — PDF・Word・テキストから、ブラウザ内で文字を取り出す
- [config.js](config.js) / [style.css](style.css) — 接続設定(公開前提の値のみ)/ 共通スタイル
- [worker/](worker/) — Cloudflare Worker(本人確認・利用回数管理・URL取得・Claude呼び出し)。仕様は [worker/README.md](worker/README.md)
- [supabase/schema.sql](supabase/schema.sql) — テーブル・ファイル保管・利用回数の管理関数(すべて行レベルセキュリティ付き)
- [SETUP.md](SETUP.md) — セットアップ手順、費用の目安、個人情報の扱い
- [PROMPT.md](PROMPT.md) — (参考)AIチャットで模擬面談をしてもらう場合のシステムプロンプト
